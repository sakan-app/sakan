# SAKAN — Folder Structure

## Purpose

This document explains the responsibility of every directory under `src/`,
plus `public/`, `supabase/`, and the top-level configuration files, so that a
new contributor can find (and place) code correctly. It also documents the
project's file-naming conventions.

## Top-Level Layout

```
src/
  assets/          static images used at build time
  components/      shared/presentational React components
  hooks/           cross-cutting React hooks
  i18n/            localization strings and helpers
  integrations/    generated/auto-managed third-party client glue
  lib/             business logic: server functions, queries, realtime, types
  routes/          file-based TanStack Router routes
  routeTree.gen.ts generated route tree (do not edit)
  router.tsx       QueryClient + Router factory
  server.ts        SSR server entry wrapper (error normalization)
  start.ts         TanStack Start config (middleware wiring)
  styles.css       global Tailwind entry
public/            static files served as-is + PWA assets
supabase/          Postgres migrations + local Supabase config
```

## `src/routes/`

File-based routing root (see `src/routes/README.md`, reproduced in
[ROUTES.md](./ROUTES.md)). Every `.tsx`/`.ts` file here defines a route via
`createFileRoute(path)`. Sub-areas:

| Path | Responsibility |
|---|---|
| `__root.tsx` | App shell: HTML document, global providers, marketing/app-shell chrome switch. |
| `index.tsx`, `about.tsx`, `guide.tsx`, `pricing.tsx`, `search.tsx`, `member.$id.tsx`, `privacy.tsx`, `terms.tsx`, `impressum.tsx`, `offline.tsx`, `unauthorized.tsx` | Public marketing/content pages, mostly SSR'd. |
| `auth.index.tsx`, `auth.callback.tsx`, `auth.reset-password.tsx` | Sign-in/up, OAuth callback, password reset. |
| `sitemap[.]xml.ts` | Dynamic XML sitemap handler. |
| `_authenticated/` | Layout route (`route.tsx`) + every page requiring a signed-in session, rendered inside `AppShell`. |
| `admin/` | Layout route (`route.tsx`) + staff-only console pages, rendered inside `AdminLayout`. |
| `api/public/` | Plain HTTP handlers outside the site's auth model (Stripe webhook, push dispatch). |

`routeTree.gen.ts` at `src/` is regenerated by the TanStack Router Vite
plugin on every route file change; it must never be hand-edited.

| `legal/` | `LegalPage.tsx` — shared layout for legal content pages. |

## `src/lib/`

Business logic layer. Most features follow the pattern described in
[Naming Conventions](#naming-conventions): `*.functions.ts` (client-safe
server-fn surface), `*.server.ts` (server-only implementation), `queries.ts`
(TanStack Query reads), `realtime.ts` (live subscriptions), `strings.ts`
(i18n copy), `types.ts` (shared types).

| Directory/File | Responsibility |
|---|---|
| `account/realtime.ts` | Realtime subscription for the signed-in user's own account state (subscription, payments, verification, featured queue). |
| `admin/` | Admin console: `admin.functions.ts`/`admin.server.ts` (role assertions), `ops.functions.ts`/`ops.server.ts` (dashboard, users, verification, reports, matches, conversations, notifications, analytics, activity, settings RPCs), `billing.server.ts` (admin billing operations), `strings.ts`, `types.ts`. |
| `ads/` | Featured-ad CRUD/queries (`ads.functions.ts`, `ads.server.ts`, `queries.ts`, `strings.ts`, `types.ts`). |
| `ai/` | Lovable AI Gateway integration: `gateway.server.ts` (HTTP client), `prompts.ts`, `assist-strings.ts`, and per-feature `*.functions.ts` + `*-helpers.server.ts` pairs for coaching, matchmaking, moderation, translation, plus `visibility.server.ts` for feature gating. |
| `audio/engine.ts` | Audio playback engine (call/notification tones). |
| `auth-errors.ts` | Maps Supabase auth error codes to localized user-facing messages. |
| `auth/offline-session.ts` | Offline-tolerant session resolution for route guards (`resolveGuardUser`, `isOffline`, `isNetworkAuthError`). |
| `billing/` | Stripe billing: `billing.functions.ts` (client RPCs), `billing.server.ts`, `stripe.server.ts` (SDK + signature verification), `customers.server.ts`, `provider.server.ts` (provider abstraction), `webhook.server.ts` (event handlers), `queries.ts`, `strings.ts`, `types.ts` (incl. `resolveEntitlements`, `FREE_ENTITLEMENTS`, `formatPrice`). |
| `calls/` | WebRTC calling: `CallProvider.tsx` (React context/state machine), `calls.functions.ts`/`calls.server.ts` (signaling RPCs), `tones.ts`, `strings.ts`, `types.ts`. |
| `chat/` | Messaging: `queries.ts`, `realtime.ts`, `reactions.ts`, `wallpaper-queries.ts`, `wallpapers.ts`, `strings.ts`, `wallpaper-strings.ts`, `types.ts`. |
| `company.ts` | Static company/brand metadata. |
| `countries.ts` | Country list, codes, and flag helpers. |
| `error-capture.ts` / `error-page.ts` | Global error capture hook (used by `src/server.ts`) and the fallback HTML error page renderer. |
| `gallery-queries.ts` | Profile gallery photo queries/mutations. |
| `i18n.tsx` | `I18nProvider`, `useI18n`, `format()` — runtime localization context. |
| `legal/` | Static legal content (about, guide, impressum, privacy, terms) plus shared `types.ts`. |
| `lovable-error-reporting.ts` | Client-side error reporting hook used by root error boundaries. |
| `members.ts` | Member search/listing queries (`activeMembersQuery`, `searchMembersQuery`, `PAGE_SIZE`, `Gender` type). |
| `notifications/` | `shared.ts`, `sounds.ts` — notification payload shaping and sound cues. |
| `outbox.ts` | IndexedDB write outbox + `fetch` interceptor for offline resilience. |

| `push/` | `push-browser.ts` (browser subscription management), `push.functions.ts` (persist subscription RPC), `webpush.server.ts` (VAPID send + fan-out logic). |

## `src/hooks/`

Cross-cutting React hooks not tied to one feature folder in `lib/`:

| File | Responsibility |
|---|---|
| `use-mobile.tsx` | Responsive/viewport breakpoint detection. |
| `useAuth.tsx` | `AuthProvider`/`useAuth` — session/user state, sign-out, router/query invalidation on auth events. |
| `useNotifications.ts` | Notification list queries + `useNotificationsRealtime`, `useUnreadCount`. |
| `usePresence.ts` | Online presence + last-seen heartbeat. |
| `useSubscription.ts` | Combines plan + subscription queries into a single `entitlements` object. |

## `src/integrations/`

Third-party client glue, largely **auto-generated** — files carry an
explicit "This file is automatically generated. Do not edit it directly."
header and should be regenerated rather than hand-edited.

| Directory/File | Responsibility |
|---|---|
| `lovable/index.ts` | Lovable platform integration helpers (e.g. OAuth/magic-link entry points used by `auth.index.tsx`). |
| `supabase/client.ts` | Browser/SSR-read Supabase client (publishable key, respects RLS). |
| `supabase/client.server.ts` | `supabaseAdmin` — service-role Supabase client for server-only privileged operations. |
| `supabase/auth-attacher.ts` | Client `functionMiddleware` attaching `Authorization: Bearer <token>` to every server-fn call. |
| `supabase/auth-middleware.ts` | Server `functionMiddleware` (`requireSupabaseAuth`) validating the bearer JWT and injecting `{ supabase, userId, claims }`. |
| `supabase/types.ts` | Generated `Database` type from the Supabase schema. |

## `src/i18n/`

| File | Responsibility |
|---|---|
| `index.ts` | Locale registry (`localeOrder`, `localeNames`, `localeFlags`) and root i18n exports. |
| `feature.ts` | `useFeatureStrings()` — per-feature localized string composition. |
| `locales/{ar,de,en,fr}.ts` | Per-language string tables. Arabic (`ar`) is the default/primary locale (the app ships RTL-first). |

## `src/assets/`

Build-time static assets: `hero-couple.jpg` (landing page hero),
`sakan-logo.png.asset.json` (Lovable-managed asset reference), and
`members/` (placeholder/demo member photos used in seed content).

## Root-level `src/*` files

| File | Responsibility |
|---|---|
| `router.tsx` | `getRouter()` — constructs the shared `QueryClient` (cache/retry policy) and `TanStackRouter` (preloading, scroll restoration, default error/pending components) used for both SSR and client hydration. |
| `server.ts` | Production server entry: wraps the generated TanStack Start server handler to catch and normalize catastrophic SSR failures (including h3-swallowed errors) into a proper HTML error page. |
| `start.ts` | TanStack Start configuration: registers `attachSupabaseAuth` as global `functionMiddleware` and `errorMiddleware` + `createCsrfMiddleware` as `requestMiddleware`. |
| `styles.css` | Global Tailwind v4 entry point, imported via `?url` in `__root.tsx`. |
| `routeTree.gen.ts` | Generated by `@tanstack/router-plugin`; never hand-edited. |

## `public/`

Static files served verbatim and PWA assets:

| File/Dir | Responsibility |
|---|---|
| `manifest.webmanifest` | Authoritative PWA manifest (name, icons, shortcuts, screenshots) — `vite-plugin-pwa` is configured with `manifest: false` to defer to this file. |
| `sw-push.js` | Hand-written service worker logic (push, notification click, sync) merged into the generated `/sw.js` via `importScripts`. |
| `offline.html` | Self-contained, JS-free offline fallback page for a cold start on a never-visited URL. |
| `icons/` | App icons (including maskable variants) referenced by the manifest. |
| `screenshots/` | Store/manifest screenshots (desktop/mobile home & search). |
| `favicon.ico`, `robots.txt` | Standard site files. |

## `supabase/`

| File/Dir | Responsibility |
|---|---|
| `config.toml` | Local Supabase project configuration. |
| `migrations/` | Timestamp-ordered SQL migrations (35 files) defining the full schema, RLS policies, functions/triggers (e.g. the notification push-dispatch trigger, `is_staff`/`is_super_admin` RPCs, `webhook_events`). |

## Top-level Config Files

| File | Responsibility |
|---|---|
| `vite.config.ts` | Vite configuration via `@lovable.dev/vite-tanstack-config` (which already wires TanStack Start, React, Tailwind v4, path aliases, Nitro build target); this project additionally configures `vite-plugin-pwa` (Workbox `generateSW` strategy, runtime caching rules) and React dependency optimization/dedupe settings. |
| `package.json` | Dependencies/scripts (`dev`, `build`, `build:dev`, `preview`, `lint`, `format`). Notable stack deps: `@tanstack/react-start`, `@tanstack/react-router`, `@tanstack/react-query`, `@supabase/supabase-js`, `react@19`, `tailwindcss@4`, `vite-plugin-pwa`, `zod`. |

## Naming Conventions

| Pattern | Meaning |
|---|---|
| `*.functions.ts` | Client-callable `createServerFn` RPC surface for a feature. Safe to import from React components/hooks; heavy or secret-dependent logic is lazily `import()`-ed inside handlers rather than imported at module top level. |
| `*.server.ts` | Server-only implementation module (uses `supabaseAdmin`, `process.env` secrets, third-party SDKs like Stripe/web-push). Must never be imported from a client-rendered component. |
| `strings.ts` | Localized UI copy for one feature, typically keyed by locale and consumed via `useI18n`/`useFeatureStrings`. |
| `queries.ts` | TanStack Query `queryOptions` factories for direct, RLS-protected browser reads against Supabase. |
| `realtime.ts` | `useXRealtime()` hooks subscribing to Supabase Realtime (`postgres_changes`/broadcast/presence) and patching the TanStack Query cache. |
| `types.ts` | Shared TypeScript types/interfaces for a feature. |
| `<name>.$id.tsx` / `<name>.\$id.tsx` | Dynamic route segment (`:id`) in file-based routing. |
| `_<name>` (e.g. `_authenticated`) | Pathless layout route — contributes a layout/guard, not a URL segment. |
| `<name>[.]xml.ts` | Escaped literal dot in a route filename (`sitemap.xml`), since a bare `.` would otherwise be parsed as a route segment separator. |
